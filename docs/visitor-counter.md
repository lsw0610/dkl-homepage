# 방문자 집계 연결

홈페이지 하단의 오늘 방문자 수와 총방문자 수는 별도의 Google Apps Script와 구글 시트에 기록합니다. 기존 상담 접수용 Apps Script에는 방문자 요청을 보내지 않습니다.

## 집계 기준

- 한국 시간(Asia/Seoul)으로 하루를 구분합니다.
- 같은 브라우저의 익명 방문 ID는 하루 한 번만 집계합니다. 새로고침과 화면 전환으로 중복 증가하지 않습니다.
- 총방문자 수는 연결한 시점부터의 일별 방문자 수를 합한 값입니다. 이전 방문 기록은 복원되지 않습니다.
- 사람의 실명이나 연락처, IP 주소는 수집하지 않습니다. 브라우저에는 무작위 ID를 저장하고 시트에는 그 ID의 SHA-256 해시와 방문 날짜를 기록합니다.
- 다른 브라우저·기기, 비공개 창, 저장소 삭제 후 방문은 별도 방문자로 집계될 수 있습니다. 브라우저의 로컬 저장소를 사용할 수 없으면 중복 집계를 피하기 위해 방문 기록을 전송하지 않습니다. 사람의 정확한 수나 봇을 완전히 제외한 분석 지표는 아닙니다.

## 관리자 설정

1. [Google Apps Script](https://script.google.com/home)에서 **새 프로젝트**를 만듭니다. 상담 접수 프로젝트를 수정하거나 교체하지 마세요.
2. 기본 코드를 지우고 `apps-script/visitor-counter.gs`의 전체 내용을 붙여 넣습니다.
3. 편집기에서 `setupVisitorCounter` 함수를 선택해 한 번 실행하고 구글 시트 접근을 승인합니다. 실행 로그의 링크가 집계 시트입니다. 같은 함수를 다시 실행해도 기존 집계는 유지됩니다. 이 시트는 공개 공유하지 않습니다.
4. **배포 → 새 배포 → 웹 앱**을 선택합니다. 실행 사용자는 **나**, 액세스 권한은 **모든 사용자**로 설정해 배포합니다. 조직 정책으로 공개 웹 앱 배포가 금지돼 있다면 해당 계정으로는 이 방식이 동작하지 않습니다.
5. 발급된 `/exec`로 끝나는 웹 앱 URL을 홈페이지 `script.js`의 `CONFIG.visitorApiUrl`에 넣습니다. 기존 `CONFIG.apiUrl`은 상담용이므로 그대로 둡니다. 공개 배포 URL만 넣고 비밀번호나 토큰은 넣지 않습니다.
6. 변경된 홈페이지 파일을 실제 서비스 저장소에 반영하고 GitHub Pages 배포를 완료합니다. 로컬 파일 수정만으로 공개 홈페이지는 바뀌지 않습니다.
7. 실제 도메인에서 처음 접속하면 오늘·총방문자 수가 증가하는지 확인하고, 같은 브라우저로 새로고침했을 때는 증가하지 않는지 확인합니다. 다른 브라우저에서는 각각 1 증가해야 합니다. 테스트도 실제 집계에 포함됩니다.

실행 코드를 바꾼 뒤에는 **배포 관리 → 수정 → 새 버전**으로 기존 웹 앱 배포를 갱신합니다. 같은 Apps Script 프로젝트의 스크립트 속성과 시트를 유지하면 누적 집계도 유지됩니다. 시트 행, 헤더, 스크립트 속성 `DKL_VISITOR_SPREADSHEET_ID`를 수정하거나 삭제하면 집계가 손상될 수 있습니다. 헤더에는 편집 경고가 설정되어 있습니다.

## 동작과 장애 처리

시트의 `Visits` 탭에는 한국 날짜(`date_kst`)와 익명 ID 해시(`visitor_hash`)가 한 줄씩 저장됩니다. Apps Script 잠금으로 동시에 들어온 같은 방문자의 요청도 한 번만 기록합니다. 기록 후 응답이 유실돼 재시도되더라도 같은 날에는 중복 집계하지 않습니다. 서버 재배포나 날짜 변경으로 총방문자 수를 초기화하지 않습니다.

홈페이지는 숫자를 임의로 생성하지 않습니다. 집계 URL이 아직 없거나 응답이 실패하면 실제 집계 수치를 표시하지 않습니다. 실제 운영 검증에는 Google 계정으로 웹 앱을 배포하고 해당 주소를 연결하는 과정이 필요합니다.

이 구현은 방문할 때마다 시트 기록을 읽으므로 소규모 사이트용입니다. 트래픽이 커지면 Apps Script 실행 시간·동시 실행·시트 할당량을 고려해 전용 분석 서비스나 데이터베이스로 이전해야 합니다. 공개 엔드포인트에 대한 허위 요청을 완전히 차단하지는 못합니다.

## 개발 검증

로컬 자동 검증은 저장소에서 `node --test tests/visitor-counter-backend.test.cjs`를 실행합니다. 실제 Google 계정이나 운영 시트에 기록하지 않고 중복 방문, 한국 자정, 영구 저장, 입력 검증, 응답 안전성을 검사합니다.

현재 클라우드 환경에는 Playwright와 `/usr/bin/chromium`도 제공됩니다. `node --test tests/visitor-counter-browser.test.cjs`로 휴대폰 레이아웃, 브라우저 ID 유지, 응답 출처·토큰 검사, 숫자 표시, 저장소 차단 시 동작을 검증합니다. 브라우저 테스트는 모의 서버를 사용하며 외부 요청을 차단하므로 실제 방문 기록이나 문의를 만들지 않습니다. 다른 컴퓨터에서 실행하려면 Playwright와 Chromium을 먼저 준비해야 합니다.

로컬 브라우저에서 실제 Google 연동까지 검증하려면 운영 프로젝트와 별도의 테스트 프로젝트·시트를 만듭니다. 테스트 프로젝트의 `VISITOR_ORIGINS`에 `http://127.0.0.1:8000`을 임시 추가하고 테스트용 배포 URL을 연결합니다. 운영 배포의 허용 출처는 `https://dkleng.co.kr`와 `https://www.dkleng.co.kr`로 유지하세요.
